먼저 저장소 루트의 `DOORAY.md`를 읽고 공통 실행 규칙을 따른다.

경로는 항상 `>` 앞뒤를 공백 한 칸으로 맞추고(`Visualizer>test` → `Visualizer > test`) 따옴표로 감싸 실행한다. Windows `dooray` launcher는 공백 없는 `>`를 리다이렉션으로 해석해 엉뚱한 페이지에 쓸 수 있다. 모든 명령은 저장소 루트에서 실행한다.

1. 인자를 대상 경로와 내용으로 나눈다. 내용은 문구이거나 로컬 파일 경로다. 제목에 공백이 있어 경계가 모호하면 해석한 경로를 4번 확인에서 보여준다. 내용이 없으면 묻는다.
2. 경로가 없거나 끝이 `>`면 쓸 위치를 고른다. `dooray wiki-read ["<경로>"]`의 첫 줄(현재 경로)과 번호 목록을 보여주고 아래 선택지를 덧붙여 번호·제목·문자로 고르게 한다. 선택 UI(AskUserQuestion)는 쓰지 않는다.
   - `a. 여기에 이어쓰기` — 대상은 첫 줄 경로. 첫 줄이 위키 이름뿐(Home)이면 이 선택지는 내지 않는다.
   - `b. 하위에 새 페이지` — 제목을 받아 대상은 `<첫 줄 경로> > <제목>`.
   - 하위 페이지를 고르면 `"<첫 줄 경로> > <고른 제목> >"`로 다시 조회해 반복한다. 하위가 없어 본문이 나오면 그 페이지에 이어쓸지, 하위에 새 페이지를 만들지 묻는다.
3. 내용을 다듬지 말고 그대로 UTF-8 임시 파일에 쓴다. 사용자가 파일을 줬으면 그 파일을 그대로 쓴다. 로컬 `![이미지](경로)`·`[파일](경로)`는 `--file`로 전달한 파일의 폴더를 기준으로 CLI가 업로드하고 참조를 바꾼다. 문구에 상대 경로 링크가 있으면 그 기준 폴더에 임시 파일을 만들고, 기준을 알 수 없으면 묻는다.
4. 판단만 실행해 결과를 확인한다:

```
dooray wiki-write "<대상 경로>" --file "<파일>" --dry-run
```

   생성/이어쓰기 여부, 대상 경로, 올릴 내용 전체, `업로드 예정` 파일 목록을 보여주고 명시적 확인을 받는다. 이어쓰기면 `## YY-MM-DD, HH:mm` 헤더(예: `## 26-10-27, 14:05`)가 붙는다고 알린다. 오류면 그대로 알리고 멈춘다.
5. 확인되면 `--dry-run` 없이 같은 명령을 실행하고 완료 메시지와 위키 주소를 전달한다. 확인 후 대상·내용·첨부가 바뀌면 판단과 확인을 다시 진행한다. 거절하면 쓰지 않는다. 3번에서 직접 만든 임시 파일만 제거하고 사용자가 준 파일은 보존한다.

실패하면 출력 전체를 그대로 알리고 자동으로 재시도하지 않는다. 이미 생성된 페이지나 업로드된 파일 안내도 함께 전달한다. 본문 변경으로 중단됐다면 최신 내용을 읽고 확인한 뒤에만 다시 진행한다.

내용의 `@이름`은 실제 멘션으로 바뀌어 알림이 간다. 글은 API 토큰 소유자 명의로 작성된다.
